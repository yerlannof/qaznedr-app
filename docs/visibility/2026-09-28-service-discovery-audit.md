# Service discovery / mobile — 28.09.2026

## Уточнение цели

Владелец подтвердил: карта — поисковое намерение, не обязательный продукт сайта. Человек должен понять, что геологи могут помочь с задачей, и написать в WhatsApp/WeChat. Не ждать файл карты ВКО и не строить интерактивную карту как условие продвижения. Реальные данные/права публикации проверяются отдельно, если такая публикация будет заказана.

## Что проверено

- Код: metadata helper даёт самостоятельный canonical, пять language-alternates (включая x-default), OG, description; robots разрешает публичные страницы. Service/Article/Breadcrumb JSON-LD уже присутствуют. Карта-гайд есть на четырёх языках, включён в sitemap (208 URL).
- Production: главная, услуга геологии и карта-гайд на всех четырёх языках — 12 HTTP 200; canonical соответствует URL, один H1, description, OG и пять hreflang присутствуют; index/follow. Это доступность/разметка, не доказательство индексации или цитирования.
- Мобильная геосцена 375×812: после hydration `data-mode=manual`; 01/02/03 доступны. Scroll-анимация сознательно ограничена 1024×740 в коде и утверждённом показе10. Поэтому отсутствие движения при мобильной прокрутке воспроизводится. Фиксированная кнопка связи может перекрыть часть панели, если панель оказывается у нижнего края экрана. Предложение12 учитывает отступы и расположение controls.

## Доступное техническое улучшение

Карта-гайд передаёт `service=geology` в существующую closing contact ссылку. Это сохраняет тему в форме и дальнейших каналах, без изменения утверждённых текстов. Другие статьи сохраняют прежний маршрут. Тест воспроизвёл отсутствие параметра до исправления.

## Следующее содержательное улучшение — на утверждение

[Конкретный текст](../copy/2026-09-28-map-service-discovery-draft.md) для существующей страницы геологических услуг: помощь с картами/материалами по заданному региону, что сообщить геологам, ограничения выводов, контакт. Соответствующий title/description отражает видимый текст. Не выпускать пустые страницы на каждый металл×регион×язык. Сначала этот полезный блок на четырёх языках; затем проверять запросы и обращения, выбирать следующие реальные темы.

Legacy `/map` остаётся редиректом на `/leads`: это ранее была карта marketplace, и без доказательств входящего намерения менять её на редакционную статью не следует. Новый контент доступен через действующие внутренние ссылки.

## Первичные рекомендации, проверены live

- [Google: оптимизация для генеративного поиска](https://developers.google.com/search/docs/fundamentals/ai-optimization-guide), HTTP 200. Нужны индексируемые полезные страницы с доступным текстом, внутренними ссылками и соответствующей видимому тексту разметкой. Специальные AI-файлы/особая schema не требуются. llms.txt оставляем справочным, не считаем механизмом гарантированного попадания в ответы.
- [Google: descriptions и сниппеты](https://developers.google.com/search/docs/appearance/snippet), HTTP 200. Description должен точно описывать конкретную страницу; списки ключевых слов хуже объясняют её пользу. Google может сформировать сниппет из основного текста и менять его под запрос.

Для Bing/Яндекса/китайских сервисов не переносим эти правила как обещание одинакового ранжирования. Фактическое появление оцениваем в каждом кабинете и по обращениям; метаданные не гарантируют верхние позиции.
