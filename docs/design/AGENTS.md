# Рабочие предпочтения владельца

По постоянной просьбе владельца от 2026-09-26 используй субагентов для дизайн-сессий. Основной агент — дизайн-руководитель и оркестратор: определяет концепцию, декомпозирует работу, проверяет качество и общается с владельцем. Простые операции делегируй.

Указанные маршруты моделей — предпочтение по усилиям и стоимости, не гарантия цен. Выбирай только из реально доступных моделей; недоступную экономную модель не подменяй молча дорогой:

- `gpt-6-luna` с `low` — простые правки, поиск и форматирование;
- `gpt-6-sol` с `low` или `medium` — HTML/CSS-прототипы и более сложная сборка внутри `docs/design/`;
- сложные концепции и финальная проверка — у ведущего агента.

Передавай минимум контекста (используй `fork_turns: "none"`, если поддерживается), узкую задачу, точные файлы и критерии результата; проси короткий отчёт. Не дублируй работу агентов. Повышай effort при необходимости. Не запускай агента для каждой микрокоманды, если накладные расходы выше самой операции. По умолчанию — один исполнитель; нескольких подключай только для независимых задач без пересечения файлов.

С 2026-09-26 ведущий агент (Astra) отвечает и за код: верстает утверждённое, коммитит, пушит в `master` и проверяет прод по корневому `AGENTS.md`. **Дизайн-субагенты** по-прежнему пишут только в `docs/design/`, не трогают `src/` и конфигурацию, не ставят npm-пакеты, не коммитят и не деплоят — это делает ведущий. Владелец утверждает дизайн по процессу из корневого `AGENTS.md` и `BRIEF.md`; до утверждения остановись на вариантах для выбора.
