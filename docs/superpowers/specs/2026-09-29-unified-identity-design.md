# Единая идентичность для закрытой площадки

Продолжение по поручению «давай дальше». На проде доступен только credentials-провайдер администратора (проверен /api/auth/providers); обычных рабочих users по предыдущему аудиту нет. Не включаем новую регистрацию и не выбираем SMS-провайдера.

- Действующий env-admin вход и его ограничение попыток сохраняются. Удаляем неработающий fallback чтения password из users через anon-клиент. Credentials остаётся исключительно административным входом.
- Существующий Google OAuth адаптер переводим на закрытый флаг MARKETPLACE_IDENTITY_ENABLED плюс настроенные Google credentials. Проверяем verified email, subject==providerAccountId и совпадение email профиля/пользователя. Не связываем аккаунты по одному email; адрес администратора зарезервирован.
- Одна транзакция создаёт marketplace_accounts и существующий profiles с тем же ID и ролью user. Повторный вход по тому же provider/subject возвращает тот же ID и не перезаписывает роль или данные профиля. Смена email/конфликт требуют отдельного безопасного процесса, в этой версии отказ.
- Accounts и profiles закрыты для anon/authenticated; только серверный service_role. Миграция проверяется локально, в production не применяется. Пароли, access/refresh token и документы не сохраняются.
- Центральный auth.config используется всеми getServerSession через совместимый re-export lib/auth/index. Административный shortcut требует одновременно env-admin ID и соответствующий email, одного совпадения email недостаточно.
- POST /api/auth/register остаётся404. UI входа и способы восстановления пока не запускаются. Этот этап проверяет provider callback→атомарное создание→стабильный JWT/session ID; полноценный живой OAuth требует настроенного клиента и одобренного запуска.
