# IndexNow — достоверный результат отправки

27.09.2026. Продолжение 6/7 по поручению выполнять доступную работу без владельца. Старт: HEAD/origin/master/Production `2f8d29f`, deployment 6690235686 success.

## Дефект

`src/app/api/indexnow/route.ts` возвращает HTTP 200 и `success: true` для любого HTTP-ответа IndexNow, включая 400/403/429/500. GET предлагает скрытый адрес `/ru/listings/123`. Операционный отчёт нельзя считать достоверным при отклонении запроса.

## Изменение

- Проверять `response.ok`: при upstream-ошибке HTTP 502, `success: false`, исходный `status`, `submitted: 0` и короткая техническая ошибка без содержимого upstream.
- При сетевом исключении HTTP 502 и `success: false`, без выдуманного upstream status. Успешная отправка сохраняет совместимые поля ответа.
- Ошибочный JSON тела вернуть HTTP 400 до fetch; требовать непустой массив непустых строк. Уточнение личного review: числа/null внутри массива сейчас бросают `.startsWith`, поэтому без этой проверки клиентская ошибка ошибочно станет upstream 502. Проверка host/protocol, лимитов и иное расширение схемы URL не входит в эту правку.
- GET должен использовать существующий публичный адрес `/zh/leads` и явно различать приём URL и индексацию.
- Авторизацию admin/shared secret, rate limit, публичный verification-файл и ключ не менять.

[Официальный протокол](https://www.indexnow.org/documentation), проверен 27.09: 200 — URL принят, 202 — принят, проверка ключа ожидается; ни один не подтверждает индексацию. 400/403/422/429 — ошибки. Тесты используют заглушки, реальные URL повторно не отправляются.
