## Smallest credible return

1. **Foundation, still private.** Choose one registration/login/session identity and one listing persistence path; repair owner reads and edit authorization; disable trusted-seller auto-publication. Prove the path registration → login → draft → submit → admin approval/rejection → public view → owner edit/unpublish with focused tests. Keep redirects until this passes. Existing legacy marketplace test suites are recorded as failing in `AGENTS.md`, so their presence is not launch evidence.
2. **Equipment rental first.** Use a distinct, moderated listing model with a few clear fields: offer mode (rent/sale), equipment category (including drilling rigs and tractors), location, availability/terms, images, and a contact action. Reuse taxonomy only where labels fit. Four-language copy and a simple large-control mobile flow for 50–60-year-old users need owner-approved content/design; no map or mineral coordinates should be required to advertise a machine.
3. **Third-party mineral areas and assisted sale.** Add a separate seller-provenance and rights-verification workflow, mineral/region/evidence fields with dated resource-standard claims, and manual editorial approval. Keep them visually and technically distinct from QAZNEDR-curated teasers. An “assisted sale” option needs an owner decision on service terms and how the request reaches the team before public copy or UI is built.
4. **Open discovery only with inventory.** Once moderated listings exist, revise hidden-route redirects, locale navigation, canonical/hreflang/sitemap, and internal links; then verify all four languages and mobile/desktop before indexing.

Key reopening risks: incomplete cross-store auth/persistence, draft visibility under RLS, public claims from unverified sellers, auto-moderation bypass, and a blank or untranslated public marketplace. They are code-level findings, not a live end-to-end failure claim.
