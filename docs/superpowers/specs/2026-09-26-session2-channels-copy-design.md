## 1. Цель

Сайт должен приносить обращения в WeChat и WhatsApp и попасть в индекс поисковиков. Для этого на нём не должно остаться текстов старой модели («маркетплейс», «продаём пакет данных за 1 000 000 ₸», «оплата», «из госархивов»): они нарушают красные линии (§3 родительской спецификации) и путают инвестора.

**Готово, когда:**

- контакты видны, тестовая заявка доходит до БД и видна в `/admin`;
- на публичных страницах нет формулировок из §4.9 (проверяет тест);
- sitemap отправлен в Google, Яндекс и Bing, IndexNow отвечает 200;
- build зелёный, новых падений тестов нет, задеплоено.

## 5. Технические долги из ревью Фазы 1

1. **Заявка.** `elapsedMs` становится обязательным: без него — 400, быстрее 2 с — тихий «успех» без записи, как сейчас.
2. **Вход владельца:**
   - лимит попыток считаем по IP + email, а не только по email, чтобы чужой человек не мог заблокировать вход владельцу, зная его email;
   - для незнакомого email выполняем фиктивный `bcrypt.compare`, чтобы время ответа не выдавало, какие email админские.
3. **PATCH `/api/admin/inquiries`.** `id` (uuid) и `status` (из списка статусов) проверяем, иначе 400, а не 500.
4. **Пустые контакты:**
   - «Или оставьте заявку» показываем только если выше есть хотя бы один канал; иначе форма идёт с заголовком `contact.formTitle`;
   - на `/contact` левая колонка без каналов не рендерится, форма занимает всю ширину;
   - пропущенный уровень заголовков исправляем (h1 → h2).
5. **Заголовки страниц.**
   - Вложенные страницы (услуги, тизер) получают суффикс «| QAZNEDR HOLDING».
   - На «О нас» бренд не повторяется дважды.
6. **WeChat «复制».** Пока ID не публикуется, кнопка не показывается. Фолбэк без `navigator.clipboard` (выделить текст) — вместе с появлением ID.
7. **`next.config.ts`.** Удаляем: работает только `next.config.mjs`. Перед удалением сверяем, что в `.ts` нет настроек, которых нет в `.mjs`.
