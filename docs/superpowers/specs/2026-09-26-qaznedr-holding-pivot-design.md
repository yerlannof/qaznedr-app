# QAZNEDR HOLDING: переход от площадки к сайту компании

Дата: 2026-09-26. Статус: дизайн одобрен (план-режим). Источник: диалог с владельцем и три исследования (Китай, SEO и GEO, право РК).

## 1. Зачем

qaznedr.kz строился как открытая площадка для всех. Она не взлетела: в базе 0 зарегистрированных пользователей, 0 заявок на доступ, 0 компаний в каталоге услуг.

Бизнес при этом ушёл в другую сторону. ТОО **QAZNEDR HOLDING** проанализировало около 7000 советских геологических отчётов. По ним найдены перспективные **свободные участки из ПУГФН**. Компания продаёт иностранным инвесторам (в первую очередь китайским, также индийским) подготовку сделки по этим участкам:

- подбор участка и лицензия на клиента;
- лицензия на холдинг с последующей продажей;
- СП или earn-in;
- аналитика.

Формат сделки выбирается на встрече. Вторым планом идут консалтинг по лицензированию и полевые работы своих геологов.

**Успех:**

- иностранные инвесторы находят сайт в Google, Яндексе, Baidu и в ответах ИИ-ассистентов по запросам «медь / золото / цинк / олово / никель + Казахстан + купить / инвестировать / лицензия»;
- пишут в WeChat или WhatsApp либо оставляют заявку по конкретному участку;
- сайт вызывает ощущение сильного и надёжного эксперта.

**Не цель:** снова открывать площадку для чужих объявлений, продавать онлайн с оплатой картой.

## 3. Юридические красные линии для текстов

Метка ⚖ означает, что пункт должен подтвердить юрист РК до запуска контента на эту тему.

1. **Не утверждать и не намекать, что участок принадлежит холдингу**, если лицензии нет. Формула: «подготовленный участок: геология изучена по архивным данным, оформим лицензию под сделку».
2. ⚖ Архивные госотчёты выдаются по соглашению о конфиденциальности (Правила № 380), продавать и публиковать их нельзя. На сайте продаём **экспертизу, аналитику и сопровождение**, а не отчёты. Слова «продаём отчёты / данные» не используем.
3. Лицензию на разведку ТПИ нельзя передать в первый год действия (ст. 40). Передача прав и долей требует разрешения МПС (ст. 44–45). Порог освобождения от 25% по Закону 337-VIII ⚖. На страницах участков и в FAQ даём дисклеймер.
4. Запрещены «гарантированная доходность», «подтверждённые запасы» без указания стандарта и подача ГКЗ C1/C2 как JORC. Стандарт указываем всегда: ГКЗ / KAZRC / историческая оценка.
5. Лицензирование подаётся как консалтинг и сопровождение, а не как «доступ» к участкам.

## 5. Заявки и контакты

### 5.1 Каналы

- `src/lib/config/contacts.ts` читает env: `NEXT_PUBLIC_WHATSAPP_NUMBER`, `NEXT_PUBLIC_WECHAT_ID`, `NEXT_PUBLIC_CONTACT_EMAIL`. QR-код лежит в `public/contacts/wechat-qr.png`. Если значения не заданы, канал не показывается: никаких битых ссылок.
- Компонент `ContactChannels`:
  - на `zh` первым идёт WeChat: QR, ID с кнопкой «复制», подсказка «添加微信，注明地块编号»;
  - на остальных языках первым идёт WhatsApp: `https://wa.me/<num>?text=<локализованный текст с кодом участка>`;
  - на мобильных есть плавающая кнопка связи;
  - иконки Lucide, эмодзи нет.

### 5.2 Таблица `inquiries` (Supabase, миграция в `supabase/migrations/`)

```
id uuid pk default gen_random_uuid()
lead_code text null           -- код участка, если заявка с тизера
name text not null
company text null
country text null
channel text not null         -- 'wechat' | 'whatsapp' | 'email' | 'phone' | 'telegram'
contact text not null         -- ID / номер / email
message text null
locale text not null
source_path text null
utm jsonb null
status text not null default 'NEW'   -- NEW | CONTACTED | MEETING | DEAL | REJECTED (как в /admin/lead-requests)
created_at timestamptz not null default now()
```

RLS включена, политик для anon и authenticated нет. Читать и писать может только service role с сервера.

### 5.3 Поток

1. Форма «Обсудить участок» / «Связаться» (без входа) отправляет `POST /api/inquiries`.
2. API проверяет: zod-валидацию, honeypot-поле, rate limit (`withRateLimit` из `src/lib/middleware/rate-limiting`).
3. Запись в `inquiries`.
4. Уведомление в Telegram (`TELEGRAM_BOT_TOKEN`, `TELEGRAM_CHAT_ID`). Если отправить не удалось, заявка всё равно сохранена и видна в админке. Отдельного email-канала в Фазе 1 нет: почтовой библиотеки в проекте нет, Telegram + БД + админка достаточно.
5. `/admin/inquiries`: список и смена статуса (образец: `/admin/lead-requests`).
6. События Vercel Analytics: `inquiry_submit`, `click_whatsapp`, `wechat_copy` (QR показывается сразу, отдельного события открытия нет).

Старый поток `LeadUnlockForm` → `/api/leads/[code]/request` (нужен вход) на публичных страницах больше не используется. Механизм выдачи полного доступа (`lead_entitlements`) остаётся в админке для клиентов после NDA.

## 6. SEO и GEO

### 6.1 Техническое (Фаза 1)

- `src/lib/seo/site.ts` задаёт `SITE_URL = 'https://qaznedr.kz'`. Им заменяются локальные `BASE_URL`: `[locale]/layout.tsx`, `leads/layout.tsx`, `leads/[code]/layout.tsx`, `listings/[id]/layout.tsx`, `sitemap.ts`.
- `src/lib/seo/metadata.ts` → `buildPageMetadata({ locale, path, title, description, images? })`:
  - локализованные title и description;
  - canonical `SITE_URL/{locale}{path}`;
  - hreflang: ru, en, zh-CN, kk, x-default → ru;
  - `openGraph.locale`.
  - Тексты берутся из `src/lib/i18n/translations.ts`.
- Canonical на уровне layout удаляется. Каждая публичная страница задаёт свой.
- `<html lang>`: `ru` / `en` / `zh-CN` / `kk`. Для zh добавляется `content-language`.
- Главный хост — `qaznedr.kz`, `www` отдаёт 308 на него (настройка доменов в Vercel).
- robots: закрыть `/*/dashboard`, `/*/admin`, скрытые разделы. Бот-агентов ИИ не блокировать.
- verification через env: Google, Yandex, Bing (`msvalidate.01`), Baidu (`baidu-site-verification`).
- Organization JSON-LD и `public/llms.txt`: QAZNEDR HOLDING, БИН, sameAs. Слово «маркетплейс» убрать.

### 6.2 Контент (Фаза 3)

- **Хабы по металлам:** сначала короткий фактический абзац, затем таблица участков портфеля по металлу (без координат), контекст «металл в Казахстане», CTA.
- **Гайды (en, zh, ru):**
  - как иностранцу получить право недропользования в РК (2026);
  - процесс лицензирования ТПИ;
  - **соответствие классификаций ГКЗ ↔ KAZRC/JORC ↔ GB/T 17766**;
  - изменения 2026 (Закон 337-VIII) ⚖.
- **Китайская терминология:** 矿业权, 探矿权, 采矿权, 资源量/储量, 金属量, 品位, 股权转让, 价格面议. В title и H1 ставим 哈萨克斯坦 + 矿种 + 矿权/投资.
- **JSON-LD:** Organization, Service, FAQPage, Article, BreadcrumbList; для участков Offer без цены.

### 6.3 Вне сайта (Фаза 4, в основном задачи владельца)

- **Вебмастера:** GSC, Bing Webmaster (от Bing зависит ChatGPT), Яндекс Вебмастер, Baidu ziyuan, Sogou. Индекс Brave (Claude) набирается через внешние ссылки.
- **WeChat:** Service Account на ТОО ($99 в год) и WeCom. Публиковать статьи-гайды.
- **Порталы:** worldmr.net, srmine.com, 678ccc.cn, minelistings.com, Kazakh Invest.
- **Соцсети:** LinkedIn (компания и посты); YouTube Shorts из контента Instagram (20K) с субтитрами EN/ZH; Zhihu; Wikidata.
- **Доступ из Китая:** проверка GreatFire / 17ce / boce. Если режут — статичное зеркало `cn.qaznedr.kz` в Гонконге.
- **GEO-мониторинг раз в месяц:** 20 промптов в ChatGPT, Claude, Perplexity и DeepSeek.

## 7. Дизайн: процесс с Codex

- `AGENTS.md` в корне (его читает Codex): Codex пишет **только** в `docs/design/`, `src/` не трогает.
- `docs/design/BRIEF.md`: продукт, аудитория, тон, бренд, ограничения, экраны.
- `docs/design/tasks/NN-*.md`: задания по очереди.
  1. Логотип и айдентика.
  2. Главная.
  3. Портфель и тизер.
  4. Услуги и «О нас».
  5. Контакты и гайды.
  6. Хабы по металлам.
- Результат каждого задания Codex показывает в `docs/design/review/NN-*.html` (варианты рядом) и ждёт утверждения владельца.
- Утверждённое фиксируется в `docs/design/APPROVED.md`: что выбрано, дата. Claude переносит это в `tailwind.config.ts` (токены) и `src/components/`.
- После утверждения айдентики обновить раздел Design System в CLAUDE.md.
