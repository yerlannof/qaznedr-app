# Закрытая форма буровых объявлений17

Владелец продолжил конкретный показ17; решение записано в APPROVED.md.
Основа — equipment taxonomy v2 и утверждённый показ, без нового дизайна.

1. Четырёхъязычная форма: четыре шага, релевантные поля, связанные режимы,
   preview, явная видимость контакта. TDD компонентов/словари.
2. Client transport: сериализованные записи/фото/submit с актуальной revision;
   конфликт останавливает запись, неизвестный исход создания не повторяется
   автоматически. Проверять owner/id/схему ответов.
3. Текстовый предварительный черновик хранит только разрешённые поля без
   контактов; после входа серверный черновик. Смена аккаунта не переносит
   контактные данные. Фото только через существующий owner API.
   Технический текст sessionStorage; account-bound UUID/uncertainty localStorage
   без контактов, marker до create и UUID до снятия marker. Неизвестный исход
   восстановления блокирует повторное создание. Временные флаги заменённого
   клиента сбрасываются при новом клиенте, включая тот же owner.
4. Новый /[locale]/equipment/new — два default-off флага, noindex, без sitemap;
   Google только с доступной конфигурацией. Email пока недоступен, пока нет
   настоящего sender/persistence. Legacy login/admin и lead данные не менять.
5. Узкие тесты RED/GREEN, полный Jest против baseline, lint/build, закрытый
   браузер375/1440 ×4языка ×2темы и смоделированный HTTP путь. Отдельно указать,
   что это не live Google/email и не настоящая production модерация.
6. Независимое сильное ревью, explicit paths commit/push, exactSHA success.
