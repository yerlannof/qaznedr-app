# Субагенты и рабочие предпочтения владельца

Общее правило для всего проекта находится в корневом `AGENTS.md`; этот файл уточняет его для дизайн-сессий. Astra — ведущий и оркестратор: декомпозирует работу, принимает решения, лично проверяет итоговый diff и доказательства результата. Отдельный доступный сильный агент проводит независимое итоговое ревью diff.

Маршруты моделей — предпочтение по усилиям и стоимости, не гарантия цен. Используй только реально доступные модели; недоступную экономную модель не подменяй молча дорогой. Для простых работ во всём проекте применяются такие маршруты:

- `gpt-6-luna` с `low` — поиск, форматирование и простые правки;
- `gpt-5.6-terra` с `low` или `medium` — простой анализ и документация;
- `gpt-6-sol` с `low` или `medium` — ограниченная реализация по точному заданию.

Для дизайн-задач сохрани границы файлов: дизайн-субагенты могут работать только внутри `docs/design/`, не меняют `src/` и конфигурацию, не устанавливают npm-пакеты, не коммитят и не деплоят. Если ограниченная реализация кодовым агентом требует `src/` или конфигурации, ведущий должен явно перечислить разрешённые пути в задании; дизайн-субагентам такое разрешение не выдаётся.

Передавай минимум контекста (используй `fork_turns: "none"`, если поддерживается), одну узкую задачу, точные файлы и критерии результата; проси короткий отчёт. Не дублируй работу. По умолчанию используй одного исполнителя; несколько агентов допустимы только для независимых задач без пересечения файлов. Не запускай агента для каждой микрокоманды, если накладные расходы выше самой операции. Повышай effort при необходимости.

Владелец утверждает дизайн по процессу корневого `AGENTS.md` и `BRIEF.md`; до утверждения остановись на вариантах для выбора. Ведущий отвечает за реализацию утверждённого дизайна и её проверку; узкую кодовую задачу может поручить кодовому агенту с явно перечисленными разрешёнными путями по корневому `AGENTS.md`.
