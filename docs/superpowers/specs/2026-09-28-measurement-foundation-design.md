# Основа измерений — 28.09.2026

Владелец поручил улучшать все направления, сбор метрик и подготовку рекламы. Первая техническая поставка без изменения дизайна: исправить атрибуцию и достоверность событий существующих контактов.

## Поведение

- При входе на публичную страницу сохранять в sessionStorage на 30 минут: пять ограниченных UTM, pathname посадочной страницы и только hostname внешнего referrer. Без query/hash реферера, email, телефонов, текста формы и рекламных click-ID. Админские/auth/API маршруты не собирать.
- Это атрибуция текущей вкладки, не межвизитный профиль. Первый вход в пределах 30 минут сохраняется при внутренних переходах; после TTL начинается новый интервал. Ошибки storage не ломают сайт, остаётся текущий URL.
- В заявке sourcePath по-прежнему означает страницу отправки. В существующем JSON utm дополнительно landing_path/referrer_host — сервер валидирует длины и формат; UTM остаются клиентскими неподтверждёнными метками, не основанием авторизации.
- Сохранение заявки важнее сторонней аналитики: исключение track не должно превращать успешную отправку в ошибку/дубликат.
- wechat_copy только после успешного clipboard.writeText; дополнительно успешный contact_context_copy, click_email. Все события с locale, известным service topic/lead code; никакого содержимого контактов/формы.
- Ничего не направлять новым рекламным получателям в этой поставке. GA4/Метрика и согласия готовятся отдельно с проверкой кабинетов. Не обещать историческую рекламную аудиторию.

## Проверка

TDD: переход с tagged landing до формы, TTL, прямой вход, запрещённое хранилище/повреждённые данные, отсутствие полного referrer, неуспешный clipboard, ошибка track после успешной заявки. Затем полный Jest (baseline), lint, build, браузер и независимое ревью. Деплой через master после успешных проверок.
