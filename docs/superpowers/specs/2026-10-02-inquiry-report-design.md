# Закрытый отчёт по сохранённым обращениям

Дата: 02.10.2026. Продолжение пакета A плана investor-growth от 01.10, разрешённого владельцем. Технический отчёт, без нового публичного текста или интерфейса.

## Проверенные основания

- Vercel Production уже связывает фильтр click_whatsapp с Pages, Referrers и свойствами lead/locale/place. Повторную клиентскую атрибуцию не добавляем.
- 02.10 в inquiries ровно две записи. В обеих явно проверены QA/test-маркеры; контакты не выгружались. Исключаем только их UUID, а не произвольные имена, домены или статус REJECTED. Данные базы не меняем.
- Существующий список админки ограничен 200; его длина не годится для отчёта за период. Стадии уже есть. Публичный POST и его одинаковый ответ антиспаму остаются прежними.

## Результат

GET /api/admin/inquiries/report?from=YYYY-MM-DD&to=YYYY-MM-DD — только существующая admin/super_admin сессия. Обе даты обязательны, календарные дни Алматы (UTC+05:00), включительно. Максимум 366 дней, не позже сегодняшнего дня. Для сегодняшнего дня верхняя граница ограничена временем запуска. Неверный ввод 400; отсутствие доступа 403; любая неполная/ошибочная выборка 500 без частичного отчёта. На всех ответах private, no-store, noindex, nosniff.

Общий модуль для API и CLI читает только id, created_at, status, locale, channel, lead_code, source_path, utm. Не читает имя, компанию, контакт, сообщение. Проходит всю выборку по UUID-курсору с фиксированным верхним временем, страницами по 500, с exact count и проверкой полноты; лимит безопасности 50 000 записей, при превышении просит сузить период. Это согласованный последовательный read, не транзакционный снимок изменяемых стадий.

Выдача: период/UTC-границы/время, stored/excludedQA/included, все существующие стадии, группировка source/medium/campaign + landing_path + source_path + area + locale + channel + status. Отсутствующая атрибуция null, не выдуманный direct. Пути только публичные локализованные без query/hash. UUID и личные поля не возвращаются. Группы — сохранённые формы, не уникальные люди и не подтверждённые переговоры. Кликовые события и прямые разговоры сюда не входят.

CLI scripts/report-inquiries.ts использует тот же модуль и существующее локальное окружение; только чтение, JSON в stdout, ошибки без DB/секретных подробностей в stderr. Документированный запуск позволяет воспроизводить одинаковые периоды без новой панели/CRM. Публичный дизайн не меняется.

## Проверка

TDD: даты/високосный день/Алматы/сегодня, более 200 и 500 записей, одинаковые timestamps, точный QA allowlist, пропущенные поля, неизвестная атрибуция, все стадии, постраничная ошибка/несогласованный count/предел, auth/no-store/noindex, отсутствие личных полей. Полный Jest против baseline, lint/build, локальный HTTP и браузер. Read-only production сверка с точным count, без фиктивных заявок. Независимое сильное ревью, исправления, push и exact SHA deployment success.

Отдельно сверить наличие Telegram-переменных в Production без чтения значений. Отсутствие уведомления не выдавать за отсутствие сохранённых заявок. Новые сообщения/тестовую заявку не отправлять.
