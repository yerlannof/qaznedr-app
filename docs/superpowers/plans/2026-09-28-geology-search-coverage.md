# План расширения поискового охвата и измерения

28.09.2026. Основание: `../specs/2026-09-28-geology-search-coverage-design.md` и `../../visibility/2026-09-28-analytics-growth-audit.md`. Это план, не утверждение опубликованных изменений.

1. **Семантика и материалы.** Создать реестр групп запросов в `docs/visibility/`: фактические GSC/Вебмастер и оценки Wordstat/Keyword Planner, без выдуманных частотностей. Сопоставить с существующими URL, картами и задачами клиента. Отдельно отметить материалы владельца и права публикации. Критерий: первая очередь выбрана по спросу, данным и способности команды обработать обращение.
2. **Спецификация измерений.** Уточнить first-touch/session attribution, сроки хранения, согласие, события, исключение внутренних проверок и данные кабинетов. Точные файлы текущей реализации: `src/components/features/InquiryForm.tsx`, `ContactChannels.tsx`, `PortalWelcomeHero.tsx`, `src/app/api/inquiries/route.ts`, `src/app/[locale]/layout.tsx`. До кода утвердить схему хранения/согласия; новый UI проходит дизайн-процесс.
3. **Надёжная атрибуция.** Тест сначала: UTM landing → внутренние переходы → submit сохраняет источник; прямой заход не перетирает выбранную исходную атрибуцию; ошибка clipboard не считается успехом; не отправляются PII. Реализация в выделенном helper и действующих компонентах/API по точной спецификации. Отдельный технический коммит `fix(analytics): preserve inquiry attribution and record successful actions`.
4. **Кабинеты и реклама.** Проверить наличие ресурсов QAZNEDR GA4/Метрики, цели, домены и доступы. Подготовить конкретную конфигурацию и согласие для проверки владельцем, затем подключить. Тест: отсутствие рекламных запросов до нужного согласия, отозванное согласие учитывается, события видны в нужном ресурсе, нет дублей SPA page_view. Настройка счётчиков не означает запуск платной кампании; расходы/аудитории утверждаются отдельно.
5. **Пилот карты.** Получить доступный материал ВКО и метаданные. Подготовить текст и mockup по `docs/design/AGENTS.md` в `docs/design/review/` + `mockups/`. После «да» записать APPROVED. Не показывать выдуманный фрагмент карты как настоящий.
6. **Код пилота после утверждения.** Новый реестр материалов и `/[locale]/maps/...`; точные файлы зафиксировать после макета. Тесты: метаданные/canonical/hreflang, реальные локали/404, реестр/ссылки/права доступа, валидный material ID заявки. Обновить `src/lib/seo/pages.ts`, `public/llms.txt`, внутренние ссылки, sitemap и подходящий JSON-LD. Отдельный коммит `feat(maps): publish approved geological map pilot`.
7. **Проверка и выпуск.** Точечные Jest → полный набор с известной baseline → ESLint → production build → браузер 375/1440, light/dark, существующие языки → независимый review diff → git push origin master → дождаться production success конкретного SHA → проверить публичный URL и события. До пуша повторно сверить HEAD/origin/Production. Не включать чужие черновики.
8. **Результат и следующая очередь.** После публикации подать новые URL подходящим поисковикам, зафиксировать исходные показатели. Через 2/4/8 недель сравнить запросы/клики и обращения; расширять на 5–8 тем с реальными материалами. Если показов/кликов нет, проверить crawl/canonical/интент/содержание прежде увеличения числа страниц.

На 28.09 выполнены аудит и черновик архитектуры; пункты реализации и публикации ещё не выполнены. Документальные изменения не требуют запуска кода/сборки; все будущие изменения поведения проходят проверки выше.
