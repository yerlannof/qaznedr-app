## Проблема и результат

Технический обход всех 92 публичных URL не обнаружил ошибок статусов, canonical, языковых альтернатив или внутренних HTML-ссылок. Но после снятия старых карточек четыре гайда и описания всё ещё обещают существующие участки. Шесть страниц металлов на четырёх языках имеют почти одинаковую пустую выдачу. Главная и страница компании повторяют description.

Первый результат — достоверные тексты и самостоятельный полезный гайд для запроса «карта золота ВКО», по которому GSC уже показывает два показа. Это не доказательство большого спроса. Пользователь получает порядок поиска источников, сверки исторической географии и проверки данных; затем может обратиться к геологам. Карта, координаты частных участков и геобаза не публикуются.

## Контракт выпуска

- Утверждение точных текстов: `docs/content-drafts/2026-09-29-east-kazakhstan-gold-map.md` и `2026-09-29-catalogue-accuracy-copy.md`.
- Четыре смысловые версии RU/KZ/EN/ZH; один поисковый замысел, местные географические термины, ссылки на первоисточники. Не заявлять проверку носителем, если она не состоялась.
- Сохраняются встреча и NDA для раскрытия деталей, отсутствие обещаний владения, свободного статуса и результатов лицензирования.
- Дата редакции обновляется только у реально изменённых материалов; `lawAsOf` не менять без новой проверки закона. Юридическую часть правки перехода права перепроверить или сузить до удаления утверждения о нынешней витрине, не переписывая норму.
- Новый гайд входит в registry/sitemap, получает Article/BreadcrumbList, собственные metadata и reciprocal hreflang, внутренние ссылки из общего гайда карт и услуг. Ссылка due diligence — существующий `/[locale]/services#due-diligence`.
- Уникальный description компании — на основе её видимого содержания. Главную не переписывать автоматически.
- Пустые металлические хабы сейчас не удалять и не закрывать от индексации: отдельное решение после подготовки содержательных блоков по золоту и меди. Не создавать сетку однотипных страниц металл×область.

## Следующая редакционная очередь

1. Этот пакет: актуальность уже видимого текста + региональный гайд ВКО.
2. Содержательные страницы золота и меди: различия типов данных, задачи клиента, что можно проверить, ограничения и ссылки на гайды. Выбор геологических примеров — после проверки источника и права публикации. Новые тексты отдельно на утверждение.
3. Чек-лист геологической проверки участка до полевых работ: исходные карты, привязка, пробы, качество исторической документации. Отделить от готового юридического гайда.
4. Реальный обезличенный пример работы команды — только из предоставленного материала и с разрешением раскрытия. Не придумывать кейсы, авторов, отзывы или результаты.

## Измерение

Для каждой новой группы страниц фиксировать дату выпуска, язык, поисковую задачу и реальные данные за полные сопоставимые периоды. Разделять брендовые/небрендовые запросы; смотреть показы, клики и посадочные страницы, затем переходы к контакту. Клик WhatsApp/копирование контакта — намерение, не подтверждённая заявка. Реальные обращения подтверждает команда, без сохранения содержимого частной переписки в публичном репозитории.

По языкам мало данных — это неизвестность, не нулевой спрос. Сначала недельный контроль обнаружения/индексации, затем сравнение полных 28-дневных периодов, когда они доступны. Не обещать сроки роста и не создавать новую автоматизацию без запроса.

Для ответных систем проверять факт цитаты с датой, запросом и URL отдельно от поисковых показов и переходов. Google указывает, что для AI-функций действуют основные SEO-требования и не требуется особая разметка: [официальное руководство](https://developers.google.com/search/docs/appearance/ai-features). Для содержательной работы ориентир — [полезный контент Google](https://developers.google.com/search/docs/fundamentals/creating-helpful-content): самостоятельная польза и проверяемые сведения. `llms.txt` и schema сами по себе не гарантируют рекомендаций.
